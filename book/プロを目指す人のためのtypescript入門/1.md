- 型注釈
  - `const str: string = "footbar"`など、:stringで型を設定すること。
- 型推論
  - 上記の:stringで設定しなくてもtypescriptが値から型を推測すること。

- 静的型付けのメリット
  - 型安全性
    - ある種の間違ったプログラムをコンパイラが型チェックで検出してくれる。
    - コンパイルエラーについての考え方
      - コンパイルエラーが発生するとそれを直す必要が出てきて、手間が発生してしまうのでは？
      - ミスを発見する速度が上がる。コンパイルエラーはむしろ出たら喜ぶべきものという考え方からtypescriptが出てきている。
  - ドキュメント化
    - 下記コードを見たときに、数値型の引数を受け取り、string型の返り値を返すことがわかる。
    ```
    function repeatHello(count: number): string {
      return "hello".repeat(count);
    }
    ```
  - 入力補完

- typescriptの歴史と、重要な変更点
  - ver 1.4(2015/1)
    - ユニオン型・type文
  - ver 1.6(2015/9)
    - インターセクション型
  - ver 1.8(2016/2)
    - リテラル型
  - ver 2.0
    - strictNullChecksコンパイラ
      - 値がundefined・nullである可能性をうまく扱えなかった。
  - ver 2.1
    - mapped types
  - ver 2.8
    - conditional types
  - ver 4.1
    - テンプレートリテラル型

- トランスパイルについて
  - typescriptのコードをjavascriptのソースコードに変換すること。
  - コンパイルとも呼ばれる。
    - 本来コンパイルとはコンピュータが解釈可能な形式にプログラムを変換することのため、同意のため。
  - 基本的にtypescriptからjacascriptに変換する方法は単純で、typescript特有の部分を取り除くだけ。

- ECMAScriptについて
  - javascriptのもう一つの名前。
  - プログラムの改訂は今でもECMAScriptベースで行われる。(ES2020など)
